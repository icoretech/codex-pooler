---
title: OpenCode
description: Configure OpenCode and OMO for Codex Pooler's bounded OpenAI Responses gemma3 façade.
---

Use OpenCode's OpenAI provider family and define exactly one model:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/gemma3",
  "small_model": "openai/gemma3",
  "provider": {
    "openai": {
      "npm": "@ai-sdk/openai",
      "name": "Codex Pooler",
      "options": {
        "baseURL": "https://codex-pooler.example.com/v1",
        "apiKey": "{env:CODEX_POOLER_API_KEY}"
      },
      "models": {
        "gemma3": {
          "id": "gemma3",
          "name": "gemma3",
          "attachment": true,
          "reasoning": true,
          "tool_call": true,
          "temperature": false,
          "modalities": {"input": ["text", "image"], "output": ["text"]},
          "limit": {"context": 258400, "input": 252560, "output": 64000}
        }
      }
    }
  }
}
```

For local setup, use `http://localhost:4000/v1`. Keeping `small_model` on `gemma3` prevents title/background helpers from inventing another model. Authenticated catalog metadata is authoritative when it differs from the static limits.

For Oh My OpenAgent, set every agent and category model to `openai/gemma3` and remove `fallback_models`. Variants may remain as local UI/budget hints, but the gateway always owns the fixed reasoning policy.

OpenCode model use does not require `/mcp`; optional operator metadata uses a separate operator MCP token.
