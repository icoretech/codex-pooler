---
title: Windmill AI
description: Configure Windmill AI for Codex Pooler's bounded OpenAI chat-completions gemma3 façade.
---

Create a Windmill `customai` resource backed by a secret Pool API key:

```yaml
description: Codex Pooler runtime credential
value:
  api_key: '$var:u/<owner>/codex_pooler_windmill'
  base_url: https://codex-pooler.example.com/v1
  headers: {}
resource_type: customai
```

Configure one workspace model:

```yaml
providers:
  customai:
    resource_path: u/<owner>/codex_pooler_windmill
    models: [gemma3]
default_model:
  provider: customai
  model: gemma3
metadata_model:
  provider: customai
  model: gemma3
```

For local setup, use `http://localhost:4000/v1`. If a self-hosted Windmill server intentionally reaches a private Codex Pooler address, Windmill may require `ALLOW_PRIVATE_AI_BASE_URLS=true`; that setting belongs to Windmill.

```bash
curl -sS -X POST \
  -H 'Authorization: Bearer <windmill-user-token>' \
  -H 'Content-Type: application/json' \
  -H 'X-Provider: customai' \
  -d '{"model":"gemma3","messages":[{"role":"user","content":"Reply with: connected"}],"stream":false}' \
  "$WINDMILL_URL/api/w/<workspace>/ai/proxy/chat/completions"
```

Do not add alternate code-completion or fallback model IDs unless they use a separate provider outside this façade. Windmill stores the Pool key; `/mcp` operator metadata uses a different token.
