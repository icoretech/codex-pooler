---
title: Pi
description: Configure Pi coding agent for Codex Pooler's bounded OpenAI Responses gemma3 façade.
---

Add one custom provider model to `~/.pi/agent/models.json`:

```json
{
  "providers": {
    "codex-pooler": {
      "name": "Codex Pooler",
      "baseUrl": "https://codex-pooler.example.com/v1",
      "api": "openai-responses",
      "apiKey": "$CODEX_POOLER_API_KEY",
      "authHeader": true,
      "models": [
        {
          "id": "gemma3",
          "name": "gemma3",
          "reasoning": true,
          "thinkingLevelMap": {"xhigh": "xhigh"},
          "input": ["text", "image"],
          "contextWindow": 258400,
          "maxTokens": 128000
        }
      ]
    }
  }
}
```

For local setup, use `http://localhost:4000/v1`. Set the defaults in `~/.pi/agent/settings.json`:

```json
{
  "defaultProvider": "codex-pooler",
  "defaultModel": "gemma3",
  "defaultThinkingLevel": "xhigh",
  "enabledModels": ["codex-pooler/gemma3"]
}
```

The thinking level is only a Pi-side hint; the gateway enforces its server-owned reasoning policy. Authenticated `/v1/models.context_length` is authoritative for exposed context metadata.

```bash
export CODEX_POOLER_API_KEY=<pool-api-key>
pi --provider codex-pooler --model gemma3 --no-session \
  -p 'Inspect the repository and report the test command.'
```

Pi model use does not require MCP. Operator metadata uses a separate MCP-capable host and operator token.
